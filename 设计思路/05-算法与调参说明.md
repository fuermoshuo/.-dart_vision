# 05 算法与调参说明

本文分四部分：

1. **检测逻辑**：从图像到“灯芯中心”的完整流程，重点解释光晕怎么过滤、检测率怎么提上去；
2. **目标选择与粗瞄准**：多目标怎么分前哨站/基地，底座怎么“对准一次后锁定不动”；
3. **调参指南**：按现象查参数，按顺序调；
4. **参数速查表**：所有参数、默认值、作用。

> 默认值以 `config/dart_vision.yaml` 和 `config/hikcamera.yaml` 为准。
> 标注“本视频”的数据来自桌面上的 `飞镖测试.mp4`（720×1280，30fps，1073 帧，5 个来回）。

## 1. 检测逻辑（`dart_detector`）

### 1.1 总流程

```
BGR 图像
  │
  ├─ cvtColor → HSV
  ├─ inRange(绿色) → 绿色二值 mask
  ├─ 开运算（去小噪点）→ 闭运算（填小洞）
  ├─ findContours → 绿色候选轮廓
  │
  ├─ 主路径：候选过滤（面积 / 圆度 / 长宽比 / 填充率 / 平均 S、V）
  │    └─ 在候选 ROI 内找灯芯：
  │         ├─ 严格：V 高 + S 低（过曝白核）
  │         └─ 回退：只看 V 高（灯芯仍是绿色时）
  │
  ├─ 第二通道（每帧都跑）：全图找“白色亮核 + 绿色光环”
  │    ├─ 小核：绿环占比 ≥ core_green_ring_min（0.60）
  │    └─ 大核：绿环占比 ≥ 0.35（近距离光晕被支架切断）
  │
  ├─ 合并两条通道、去重、按 x 排序
  │
  └─ 输出 vector<DartTarget>（多目标；单目标 detect() 取最优的一个）
```

最终输出的 `center` 和 `radius` 都是**灯芯**的，不是外圈光晕的。
两条路径都输出灯芯，区别只在“怎么找到这个灯芯”。

实车使用 `detectAll()` 拿到所有引导灯；左右身份、瞄准和锁定在
`dart_track` 里完成（见第 2 节）。离线视频工具仍使用单目标 `detect()`。

调试窗口左上角（`target: FOUND` 右边）的 `FPS xx` 是检测线程每秒实际处理的帧数，
相机断流/重连时它会掉下来，可以直接拿来判断卡顿发生的时间点。

### 1.2 绿色候选与过滤

| 参数 | 默认 | 作用 | 调法 |
| --- | --- | --- | --- |
| `hue_low` / `hue_high` | 35 / 85 | 绿色 Hue 区间 | 目标偏黄降低上限，偏青提高下限；先只调这个 |
| `sat_low` / `val_low` | 60 / 60 | 绿色 mask 的饱和/亮度下限 | 目标暗时降低；环境反光多时提高 |
| `morph_kernel_size` | 3 | 开/闭运算核 | 噪点多加大到 5 |
| `min_area` / `max_area` | 150 / 20000 | 候选面积范围（像素²） | 按目标实际大小；太大排除不了大块绿色背景 |
| `min_circularity` | 0.10 | 最小圆度 | 只做粗筛，形状主要靠填充率/长宽比 |
| `max_aspect_ratio` | 2.2 | 外接椭圆长短轴比上限 | 越小越“圆”；目标+光晕常被拉长 |
| `min_fill` | 0.30 | 填充率 `area/(πr²)` | 排除细长/镂空绿色；支架遮挡时目标会掉到 0.3 |
| `min_mean_sat` | 120 | 轮廓内平均饱和度 | 排除灰绿/浅绿、UI 图标 |
| `min_mean_val` | 95 | 轮廓内平均亮度 | 排除暗绿色物体（垃圾桶、背景） |

候选评分（`dart_detector.cpp`）：

```cpp
score = fill * min(meanV/200, 1) * min(meanS/200, 1) / max(1, aspect)
```

优先选“**亮、饱和、填充率高、接近正圆**”的候选。这一步主要用于在多个绿色候选中挑一个，
真正决定框大小的是后面的“灯芯定位”。

> 近距离时灯很大，绿色光晕容易和被打亮的支架粘成一片，面积超过 `max_area`、
> 填充率也会被拉低，主路径会失效——这种情况交给 1.4 的第二通道处理，
> 不需要为了近处把 `max_area` 放到很大。

### 1.3 灯芯定位：框的是小白核，不是光晕

#### 为什么会有一个“白洞”

绿灯过曝时，核心会变成**白色**（S 很低、V≈250），而绿色掩码要求 S≥60，
所以灯芯在绿色 mask 里是一个“洞”，外面只剩一圈不规则的光晕。

如果直接用绿色轮廓，框会套在光晕上，半径能到 35~45px，而真实灯芯只有 10~15px。

#### 两阶段灯芯

在候选包围盒 ROI 内：

1. **严格模式**：`V ≥ core_val_min` 且 `S ≤ core_max_sat`
   - 对应过曝白核；
   - 绿色光晕 S 高，会被 S 上限排除。
2. **回退模式**：只看 `V ≥ core_val_min`
   - 兼容灯芯仍是绿色的情况（旧录屏、低曝光）。
3. 对灯芯做开/闭运算，找连通域；
4. 在多个灯芯里选“离绿色光晕中心最近、面积够大”的：
   ```cpp
   score = core_area / (1 + distance_to_outer_center)
   ```
   - 避免选中旁边更亮/更大的白色反光点；
5. 输出：`center = 灯芯中心`，`radius = 灯芯半径`，`area = 灯芯面积`。

相关参数：

| 参数 | 默认 | 作用 | 调法 |
| --- | --- | --- | --- |
| `core_val_min` | 240 | 灯芯最低亮度 | 灯偏暗/曝光低时降到 200~220 |
| `core_max_sat` | 90 | 灯芯最高饱和度 | 光晕偏白时降低；白核被排除时提高 |
| `core_min_area` | 50 | 灯芯最小面积 | 远距离目标可降到 30 |
| `core_min_radius` | 8 | 灯芯最小半径 | 同上 |
| `core_green_ring_min` | 0.60 | 第二通道小核的绿环占比下限 | 见 1.4；大核用内置的 0.35 |

#### 光晕为什么会被过滤掉（重点）

以本视频第 1049 帧为例：

| 掩码 | 面积 | 半径 | 结果 |
| --- | --- | --- | --- |
| `V ≥ 200` | 2960 | 39.2 | 整片光晕，太大 |
| `V ≥ 240` | 1676 | 27.0 | 仍包含大量光晕 |
| `V ≥ 250` | 1464 | 25.4 | 光晕本身也接近饱和 |
| `V ≥ 240 且 S ≤ 80` | **324** | **13.0** | 白色小核，正确 |

关键结论：**只靠亮度 V 分不开光晕和灯芯**，因为光晕也很亮；
但光晕是绿色（S 高），灯芯过曝成白色（S 低），所以加一道 **S 上限** 就能把光晕剥掉。

最终框半径从 36.7px 降到 13.8px，框贴合小白核。

### 1.4 白核 + 绿环：远近场通用的第二通道

#### 为什么要单独一条通道

主路径是“先找绿色轮廓，再在轮廓里找白核”。它在远端很稳，但有两类场景会失败：

1. **环境绿光强**：绿色外圈被打碎，面积/填充率过滤失败；
2. **近距离大灯**：灯的白核很大，绿色光晕和被打亮的支架、黑边粘成一片，
   绿色轮廓面积超过 `max_area`、填充率也被拉低，**真正的灯被筛掉**；
   而支架上“绿色反光 + 白色小亮点”反而满足主路径所有条件，
   结果框套到一个很小的反光点上（实拍：反光点 r≈16，真灯白核 r≈34~50）。

这两类场景的共同点是：**白色亮核 + 周围绿色依然可靠**。
所以第二条通道直接找“白核 + 绿环”，并且**每帧都运行**，不再只在主路径失败时兜底。

#### `findCoresByGreenRing` 流程

1. 全图找白色亮核：`V ≥ core_val_min`（240）且 `S ≤ core_max_sat`（90）；
2. 对每个核做膨胀、减去核本身，得到一圈“环”：
   - 环的厚度约等于核半径，近处大核的环也大，能覆盖整个光晕；
   - 环的统计只在核附近的小 ROI 里做，不对整幅大图做膨胀/相减；
3. 统计环内绿色像素（H 35~85、S≥100、V≥80）的占比；
4. 占比门槛**分两档**：
   - 小核（半径 < 25）：`core_green_ring_min`，默认 0.60，远端和普通白灯用这一档；
   - 大核（半径 ≥ 25）：0.35。近处白核很大，光晕会被支架、黑背景切断，
     实测绿环占比只有 ~0.5，用 0.60 会把真灯误杀；
5. 按 `绿环占比 × 核面积` 选最佳；
6. 面积限制 50~50000、半径 8~200，避免天花板灯/超大反光。

#### 两条通道怎么合并

| 情况 | 结果 |
| --- | --- |
| 第二通道没结果 | 用主路径结果 |
| 第二通道的核面积 ≥ 主路径核面积 × 2 | **用第二通道结果覆盖主路径** |
| 其他 | 保留主路径结果 |

理由：同一个灯在两条通道里应该找到同一个白核，面积接近；
如果第二通道找到一个明显更大的白核，几乎一定是主路径抓到了绿色支架上的小反光点。
这一步就是“近处大灯锁到小反光点”的修复点（`kRingOverrideAreaRatio = 2.0`）。

#### 实测数据

远端（飞镖测试视频，720×1280）：

| 帧 | 白色灯芯 | 灯芯半径 | 周围绿环占比 | 绿色外圈填充率 |
| --- | --- | --- | --- | --- |
| 440 | (508,549) | 13.0 | **0.89** | 0.19（被过滤） |
| 755 | (178,524) | 14.5 | **0.96** | 0.22（被过滤） |

普通白灯、天花板灯的绿环占比实测只有 0.00~0.46，会被小核门槛 0.60 挡掉。

近端（1440×1080 实拍，Bayer8）：

| 对象 | 白核半径 | 核面积 | 绿环占比 |
| --- | --- | --- | --- |
| 真灯 | 34~50 px | 数千 px² | 约 0.50 |
| 支架上的反光点 | 16~17 px | 数百 px² | 约 0.78 |

只按占比选会选中反光点；按“占比 × 面积”选，并且对大核放宽门槛后，真灯胜出。

#### 检测率提升过程

| 阶段 | 关键改动 | 旧录屏目标段 | 飞镖测试 |
| --- | --- | --- | --- |
| 1 | 绿色 + 形状 | 15.8% | 低 |
| 2 | + 填充率 / 平均 S/V / 长宽比 | 93.5% | 82.5% |
| 3 | + 白核 / S 上限 | 92.9% | 82.5%（框已正确） |
| 4 | + 白核绿环兜底 | 92.9% | **100%（1073/1073）** |
| 5 | 第二通道常驻 + 大核面积仲裁 | 92.9% | 近端实拍可用 |

旧录屏剩下的 7.1% 是淡出黑屏，不是目标漏检。

> 绿灯闪烁本身也会导致个别帧没有检测，这是正常的。
> 现在不再做周期中心估计，单帧丢失不会影响已经锁定的状态。

## 2. 目标选择与粗瞄准（`dart_track`）

### 2.1 为什么不再做"周期中心"

旧代码假设基地目标来回周期摆动，用 min/max 中点估计摆动中心。
2027 规则里基地目标不是这样动的：

- 固定目标：全程不动；
- 随机固定：开闸时换到随机位置并停稳，命中后再换；
- 随机移动 / 末端移动：飞镖发出后 600ms / 1.2s 换位置，600ms 内停稳。

也就是"静止 → 离散换位 → 静止"，**大部分时间是不动的**。
所以：

- 不需要周期窗口，也不需要中心估计；
- 底座只需要在开闸时把选中的目标转到画面中心，锁定后保持不动；
- 目标之后的移动交给制导镖。

### 2.2 多目标身份：左前哨站、右基地

两个引导灯在 7 分钟比赛阶段内常亮。两灯以上同时可见时：

1. 先从所有检测里**按白核面积取最大的两个**（排除小反光点/误检）；
2. 再按这两个的 x 分左右：

| 位置 | 身份 | 串口 target |
| --- | --- | --- |
| 两者中 x 较小（左） | 前哨站 | 1 |
| 两者中 x 较大（右） | 基地 | 2 |

云台纯 yaw 转动不改变左右顺序，所以这个判据**不需要 PnP / 世界坐标 / 云台角度**。
剩下的较小检测只显示、不参与身份和瞄准。

- 只剩一个灯时，先用上一次两灯都在时记录的位置匹配身份；
- **匹配不上也照样用它**：画面里只有一个灯时，不管它在图像的什么位置，
  都直接当作当前选中的目标——左右是两盏灯之间的相对关系，不能用画面绝对位置判断；
- 超过 `max_lost_ms` 没有任何灯，清空位置记忆；
- 相机左右装反时把 `swap_sides` 改成 `true`。

### 2.3 瞄准状态机

| 状态 | 行为 | 串口 state |
| --- | --- | --- |
| IDLE | 没收到目标选择，不输出瞄准 | 0 |
| ACQUIRE | 选中目标可见，输出 `target_yaw_deg`，云台转动 | 1 |
| HOLD | `|target_yaw_deg| ≤ align_tolerance_deg` 连续 `align_frames` 帧后锁定 | 2 |

HOLD 之后：

- `target_yaw_deg = 0`，`found = 1`；
- 目标再怎么移动都不再更新误差——这就是"粗对准转过去之后固定不动"；
- 电控看到 `state = 2` 应保持当前角度（即使仍按误差做 PID，误差为 0 也不会动）；
- 需要重新对准时，电控发命令 `3`。

流程：

```
收到 command = 1/2
  → 取面积最大的两个灯，再按左右分前哨站/基地
  → ACQUIRE：输出角度，云台转过去
  → 连续 N 帧 |target_yaw_deg| < 阈值 → HOLD
  → 底座保持不动，发射
  → 下一发需要重新对准：command = 3
```

### 2.4 串口命令

| command | 含义 |
| --- | --- |
| 0 | 停止 / 待机 |
| 1 | 瞄准前哨站（两个最大目标中偏左的） |
| 2 | 瞄准基地（两个最大目标中偏右的） |
| 3 | 保持当前目标，重新粗对准 |

详细字节定义见《04-串口通信协议》。

### 2.5 角度解算

针孔模型下：

```
angle_rad    = yaw_sign * atan2(center_x - cx, fx)
target_yaw_deg = angle_rad * 180 / π              // 串口发送的就是这个
```

- `fx` / `cx` 来自 `config/hikcamera.yaml` 的 `calibration.camera_matrix`；
- 角度依赖 `fx`，标定不准会有比例误差；`fx` 是相机内参，不需要 PnP；
- 没做畸变修正，目标长期在画面边缘时可后续补；
- 离线 CSV 里的 `error_x` 只是归一化像素误差，方便离线分析，不再发给电控。

### 2.6 常见现象

| 现象 | 原因 / 处理 |
| --- | --- |
| 对准后云台还在跟着灯动 | 还没进入 HOLD：检查 `align_tolerance_deg`、`align_frames` |
| 进入 HOLD 后目标移动、云台不动 | 正常，这是设计行为；需要重新对准发 command=3 |
| 两个灯身份反了 | 调 `swap_sides` |
| 只剩一个灯时身份乱跳 | 调 `role_match_norm`，或保证两灯同时可见时再开始 |
| 一直不锁定 | 阈值太严，放宽 `align_tolerance_deg`；或目标不在选中侧 |

## 3. 调参指南

### 3.1 检测调参顺序

1. **先看绿色 mask**：`detector.debug: true`，或离线 `--save out.mp4` 生成 `_mask.mp4`；
   调 `hue_low/hue_high`、`sat_low`、`val_low`，保证目标那块是白的、轮廓完整；
2. **调面积**：`min_area` / `max_area`，排除噪点和大块绿色背景；
3. **调形状**：`min_fill`、`max_aspect_ratio`、`min_circularity`；
4. **调亮度/饱和度**：`min_mean_sat`、`min_mean_val`，排除暗绿/灰绿物体；
5. **调灯芯**：`core_val_min`、`core_max_sat`、`core_min_area`、`core_min_radius`，
   保证框套在小白核上；
6. **调第二通道**：`core_green_ring_min` 只作用于小核（半径 < 25）；
   环境绿光强、漏检多时降到 0.5 左右，误检白灯时提高。
   大核（半径 ≥ 25）用的是代码内置的 0.35，不读这个参数。

每改一次参数，建议用同一段视频跑：

```bash
./build/dart_video_test "视频.mp4" --no-show --fast --csv "out/track.csv" \
  --save "out/annotated.mp4"
```

看三个东西：`检测成功率`、瞄准点/锁定情况、`_mask.mp4` 里白核是否稳定。

### 3.2 瞄准调参顺序

1. **先确认目标选择**：串口发 `1` 能转向前哨站，发 `2` 能转向基地；
2. **调对准阈值**：`align_tolerance_deg`（默认 0.3°），云台在中心附近来回微调就适当加大；
3. **调锁定帧数**：`align_frames`，太小容易误锁，太大响应慢；
4. **调身份匹配**：`role_match_norm`，只剩一个灯时身份乱跳就调整；
5. **调方向**：飞镖架转反改 `yaw_sign = -1.0`；相机左右装反改 `swap_sides: true`；
6. **重新对准**：锁定后目标移动，电控发 `command = 3`。

### 3.3 现象 → 参数

| 现象 | 优先检查 |
| --- | --- |
| 检测不到目标 | `hue/sat/val`、`min_area`、`min_mean_val`、`core_val_min` |
| 框套在整片光晕上 | `core_max_sat`、`core_val_min`、`core_min_area` |
| 框忽大忽小 | `min_fill`、`max_aspect_ratio`、多个核的评分 |
| 框套到白色反光点 | `core_green_ring_min`，或提高 `min_mean_sat` |
| 近处大灯框到支架小反光点、框很小 | 第二通道大核仲裁（内置）；确认真灯白核面积 ≥ 反光点 2 倍 |
| 近处大灯漏检 | 内置 `kFallbackMaxCoreArea`/`kFallbackMaxCoreRadius`；或降低 `core_val_min` |
| 环境绿光强时漏检 | `core_green_ring_min` 降低到 0.5 左右 |
| 过曝严重、偶发漏检 | `big_core_ring_min` 从 0.35 降到 0.20；或降低曝光/增益 |
| 对准后云台还在跟着灯动 | 还没进入 HOLD：检查 `align_tolerance_deg`、`align_frames` |
| 进入 HOLD 后目标移动、云台不动 | 正常设计；需要重新对准发 `command = 3` |
| 两个灯身份反了 | `swap_sides` |
| 只剩一个灯时身份乱跳 | `role_match_norm`，或等两灯同时可见再开始 |
| 一直不锁定 | 放宽 `align_tolerance_deg`；或目标不在选中侧 |
| 飞镖架转反 | `yaw_sign = -1.0` |

### 3.4 离线视频验证

```bash
# 只看统计
./build/dart_video_test "视频.mp4" --no-show --fast --no-csv

# 保存标注 + 掩码 + 对比视频 + CSV
# 视频统一放 out/video/，目录不存在会自动创建
./build/dart_video_test "视频.mp4" --no-show --fast \
  --csv "out/track.csv" --save "out/video/annotated.mp4"

# 视频偏暗时
./build/dart_video_test "视频.mp4" --no-show --fast --gamma 1.5 \
  --save "out/video/annotated.mp4"
```

输出都在项目根目录的 `out/` 下，不会在 `build/` 里建目录：

```
out/
├── track.csv          # 逐帧数据
├── video/             # 离线测试保存的视频（标注 / 掩码 / 对比）
└── photos/            # 现场按 s 保存的彩色截图
```

现场调试时，先点一下 SDL 窗口让它获得焦点，再按：

| 按键 | 作用 |
| --- | --- |
| `s` | 保存一帧彩色原图到 `out/photos/时间戳.png` |
| `1` / `2` / `0` | 调试用：瞄准前哨站 / 基地 / 待机（等同于串口 command） |
| `3` 或 `r` | 保持目标，重新粗对准（清掉 HOLD） |
| `ESC` | 退出（关闭窗口也可以） |

截图保存的是**原始 BGR 彩色图**，不带调试框/文字叠加，方便直接拿去离线复现或量像素。

调试时还会弹出一个 **`DartAim`** 窗口，显示：

```
AIM: ACQUIRE / HOLD / IDLE     target: OUTPOST / BASE / NONE
found=1  err=+0.0123  yaw=+0.87 deg  center=(720,540)
```

- ACQUIRE：蓝色十字在选中目标上，误差实时变化，云台应跟随；
- HOLD：品红色十字 + 方框，锁定点在画面上**不再移动**；
- 手拿相机测试：把灯转到画面中心附近停住约 0.2 秒 → 变成 HOLD；再转动相机，
  绿色检测框跟着灯走、品红色锁定框不动，就说明锁定生效；
- 按 `3` / `r` 可以退出 HOLD 重新对准。

现场运行时，调试窗口左上角（`target: FOUND` 右边）会显示 `FPS xx`，
它是检测线程每秒实际处理的帧数，和相机实际送帧速率一致；
相机卡死/重连时这个数会掉下来。相机分辨率和帧率看启动日志：

```
Camera resolution = 1440x1080
Camera PixelFormat = 0x1080009        # 0x01080009 = BayerRG8
Camera AcquisitionFrameRate = 165.9 fps
```

`AcquisitionFrameRate` 是**相机自己配置/能跑的最大帧率**，不是实际送帧速率；
实际帧率受链路带宽限制（USB 2.0 约 30~40 MB/s）。

## 5. 相机曝光建议

绿灯是闪烁光源，曝光过长会过曝成白斑、光晕变大，圆度下降。建议：

- 先调曝光，再调增益：3000 → 6000 → 8000 微秒；
- 环境暗时适当加增益（16 → 18 → 20），但噪点会增加；
- 保证灯芯是小白点、外圈不要糊成一大片；
- 快门尽量短，减轻目标平移带来的运动模糊；
- 接实车前，最好重新做一次相机内参标定，替换 `hikcamera.yaml` 里的占位值。

带宽参考（Bayer8，1 字节/像素）：

| 分辨率 | 25fps 需要 | 70fps 需要 | 165fps 需要 |
| --- | --- | --- | --- |
| 1440×1080 | 38.9 MB/s | 108.9 MB/s | 258.9 MB/s |
| 640×480 | 7.7 MB/s | 21.5 MB/s | 50.7 MB/s |

USB 2.0 实际约 30~40 MB/s。所以 1440×1080 下 25fps 基本就是上限；
想上高帧率，优先换 USB 3.0，其次降分辨率 / 裁 ROI / binning。
