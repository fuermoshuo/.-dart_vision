# 06 视频离线测试

不接相机也能验证检测和目标选择：把视频文件喂给**真实的** `DartDetector` / `DartTrack`，
逐帧显示检测框、坐标和粗瞄准点，并输出标注视频 + CSV。

> 离线工具走单目标接口：它把每帧最优的一个灯当作选中目标，
> 用来验证检测和"对准→锁定"逻辑；实车的左右分身份需要串口命令，见 04/05。

标定不参与这个过程——没标定时 `target_yaw` 没有物理意义，看 `error_x` 和中心曲线即可。

## 1. 编译

离线工具只需要 OpenCV / yaml-cpp / spdlog / SDL2，**不需要海康 SDK 和串口**：

```bash
mkdir -p build && cd build
cmake .. -DDART_VISION_OFFLINE=ON
make -j8 dart_video_test
```

> 在 Windows 上编译需要先用 vcpkg 装好上述依赖；
> 在装了 `02-依赖库与Linux编译.md` 里那些依赖的 Linux 机器上可直接编。

`DART_VISION_OFFLINE=ON` 会跳过 `hikcamera` / `serial` / `threads` 和主程序，
只生成 `dart_video_test`。不加这个选项则和原来一样编译全部目标。

## 2. 运行

```bash
# 从 build 目录运行（config 通过软链接可见）
./dart_video_test ../test.mp4

# 保存标注视频 + 逐帧 CSV（视频统一放 out/video/，目录不存在会自动创建）
# --save 还会自动生成：
#   test_out_mask.mp4    黑白掩码（白=被选中的灯芯）
#   test_out_compare.mp4 左：标注画面 / 右：灯芯掩码，方便对比
./dart_video_test ../test.mp4 --save out/video/test_out.mp4 --csv out/track.csv

# 没有显示器（如 SSH）时
./dart_video_test ../test.mp4 --no-show --save out/video/test_out.mp4

# 只看第 300 帧开始的 200 帧，快速检查
./dart_video_test ../test.mp4 --start 300 --frames 200

# 参数扫描：用另一份配置
./dart_video_test ../test.mp4 --config other.yaml
```

默认**按视频帧率实时播放**。`--fast` 可以全速处理，但涉及时间的行为（身份位置记忆）时序会失真，
只适合看检测画面对不对。

快捷键：`空格` 暂停/继续，`n` 单步，`s` 截图，`q` / `ESC` 退出。

## 3. 画面里有什么

| 元素 | 含义 |
| --- | --- |
| 绿色圆 + 黄色方框 | 本帧检测到的目标（`minEnclosingCircle` 结果） |
| 黄框旁 `(x,y) r=...` | 瞬时圆心坐标和半径 |
| 红色十字 | 瞬时圆心 |
| 品红十字 / 竖线 | 粗瞄准点（选中目标或锁定后的位置） |
| 青色竖线 `cx` | 主点（图像中心） |
| 左上文字 | 帧号、视频时间、检测状态、瞄准状态、检测耗时 |
| 左中文字 | 瞬时目标 / 瞄准点 / `error_x` / `yaw` |
| 底部曲线 | 横坐标历史：灰色=瞬时检测，绿色=瞄准点，青色=图像中心 |

看底部曲线最直观：

- 灰线随目标移动 → 检测正常；
- 绿线在接近中心后变成一条平线 → 进入 HOLD（锁定），这是预期行为；
- 绿线一直跟着灰线动 → 还没进入 HOLD，检查 `align_tolerance_deg` / `align_frames`；
- 曲线阶梯跳变 → 检测有野值，检查绿色阈值和灯芯参数。

## 4. CSV 列

| 列 | 说明 |
| --- | --- |
| `frame`, `video_time_s` | 源视频帧号 / 时间 |
| `det_valid`, `det_x`, `det_y`, `radius`, `area`, `circularity` | 本帧检测结果 |
| `found`, `error_x`, `yaw_deg` | `DartTrack` 本帧输出；`error_x` 仅供离线分析，串口只发 `yaw_deg` |
| `center_x`, `center_y` | 选中/锁定后的瞄准点 |
| `detect_ms` | 本帧检测耗时 |

## 5. 结束时的汇总

- **检测成功率**：原始检测命中率，看绿色阈值是否合适；
- **found 比例**：经过瞄准状态机后的有效输出比例；
- **最长连续未检出**：闪烁灯最容易在这里暴露问题，单位同时给帧和毫秒；
- **瞬时圆心 x 范围 vs 瞄准点 x 范围**：锁定后瞄准点应该收成一条窄范围；
- **瞄准点每帧变化**：HOLD 后应为 0；
- **检测耗时**：平均/最大，确认单帧处理能跟上相机帧率。

## 6. 注意

1. **锁定后曲线变平是正常的。** 目标再移动，瞄准点也不会更新；
   需要重新对准时，实车由电控发 `command = 3`，离线工具里可以重新跑视频。
2. **视频分辨率要和实车一致。** 检测阈值/面积过滤是按像素写的，分辨率变了检测参数要重调。
3. **标定缺失时忽略 `yaw_deg`。** 工具会提示 `fx not calibrated`，此时看 `error_x` 和像素坐标。
4. **`--fast` 下不要评估丢失行为。** 真实时间几乎不前进，`max_lost_ms` 几乎不会触发。

## 7. 常见问题

### 视频放哪里？

任意位置，路径直接作为参数传进去：

```bash
./dart_video_test ~/videos/test.mp4
```

- WSL 下建议把视频拷到 Linux 自己的目录（如 `~/videos/`），比 `/mnt/c/...` 快很多；
- 默认 CSV 写在视频旁边（`test_track.csv`），不想写就加 `--no-csv`；
- 默认配置路径是 `config/...`（**相对当前工作目录**），所以要么在 build 目录里运行，
  要么用 `--config ../config/dart_vision.yaml --camera-config ../config/hikcamera.yaml`。

### 每次都要 cmake + make 吗？

不用。

| 场景 | 要做什么 |
| --- | --- |
| 第一次 | `cmake ..` 然后 `make -j8` |
| 只改了 `.cpp/.hpp` | 只 `make -j8`（增量编译，只重编改过的文件） |
| 改了 `CMakeLists.txt` / 增删源文件 / 改编译选项 | 重新 `cmake ..` 再 `make` |
| 每次运行 | 都要 `./dart_video_test ...` |

`cmake` 只负责“生成构建规则”，`make` 才真正编译。`cmake ..` 很快，但没必要每次都跑。

### 有相机 / 无相机怎么切换？

最省事的方式是**两个构建目录**，互不干扰：

```bash
# 无相机（视频调试）
cmake -S . -B build-offline -DDART_VISION_OFFLINE=ON
cmake --build build-offline -j8 --target dart_video_test
./build-offline/dart_video_test ~/videos/test.mp4

# 有相机（完整程序）
cmake -S . -B build -DDART_VISION_OFFLINE=OFF
cmake --build build -j8
./build/dart_vision
```

注意：

- `DART_VISION_OFFLINE=ON` 时**没有 `dart_vision` 这个目标**，只有 `dart_video_test`；
- 两种模式用的是同一份算法源码，检测/瞄准结果一致，只是编不编相机和串口；
- 完整模式需要 `/opt/MVS`（海康 SDK）和串口设备；
- 也可以在同一目录里来回传参数 `cmake .. -DDART_VISION_OFFLINE=ON/OFF`，但每次都要重配，
  而且旧的可执行文件会留在目录里，容易搞混，所以推荐两个目录。

### SDL2 / spdlog 是在哪里链接的？

不在顶层 `CMakeLists.txt`，而是在各个模块自己的 `CMakeLists.txt` 里：

- **SDL2 / SDL2_image / SDL2_ttf / spdlog / OpenCV** → `rm_utils/CMakeLists.txt`
  （`find_package` 在第 7~11 行，`target_link_libraries` 在第 24~29 行）；
- **OpenCV / yaml-cpp** → `dart_aim/CMakeLists.txt`；
- **海康 MVS** → `hardware/hikcamera/CMakeLists.txt`（`/opt/MVS`，写死路径）。

`rm_utils` 用的是 `PUBLIC` 链接，所以任何链接了 `rm_utils` 的目标（`dart_aim`、`dart_video_test`）
都会自动继承 SDL2/spdlog 的头文件路径和库，不用在顶层再写一遍。
